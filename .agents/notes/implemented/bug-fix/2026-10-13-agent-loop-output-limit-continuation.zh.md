# Agent Note: 将输出上限结果与步骤调度分开

Status: implemented

[English](2026-10-13-agent-loop-output-limit-continuation.md) | 中文

## Problem

模型回复可能触及单次输出上限，但后续用户续写仍需要正常执行工具。循环会将 `max-tokens` 保留为轮次结果，同时也用这个持久结果判断当前步骤是否还欠下一次请求。续写后的回复调用工具时，步骤返回空完成原因，但粘滞的轮次结果会让循环在将已提交的工具结果发回模型之前停止。

## Decision

[agent loop](../../../../packages/core/agent-loop/src/agent.ts) 将步骤级调度与持久轮次结束原因分开跟踪。即使较早步骤让 `max-tokens` 成为粘滞轮次结果，调用工具的步骤仍会继续发起模型请求；后续步骤完成后，`turn/end` 仍记录 `max-tokens`。

聊天续写操作会记录一条明确的本地化用户消息，说明上一条回答被截断，请模型从停止处继续、不要重复已完成内容，并将较长的剩余工作拆成较小部分。这会保留用户当前的输入草稿，并使续写指令可以从 Session 日志重建。

## Alternatives considered

**提高适配器默认输出 token 上限。** 拒绝：服务端上限各不相同，推理和可见输出共用提供方预算，而且提高请求上限无法修复循环跳过必要工具结果请求的问题。

**继续用持久轮次结果作为调度信号。** 拒绝：`max-tokens` 应在轮次完成后保持粘滞，而调用工具的步骤没有步骤完成原因，仍然欠下一次模型请求。

**只发送泛化的“继续”消息。** 拒绝：持久历史没有说明上一条 assistant 消息为何停止，也没有说明如何约束剩余输出，模型可能再次生成过长内容。

## Consequences

用户可以通过现有 Conversation 发送路径续写被截断的回答；续写指令作为普通持久用户消息记录，提供方调用中被截断的工具调用仍不会执行。轮次状态和历史继续保留 `max-tokens`，后续步骤则可完成工作。这不会改变提供方输出上限，也不保证剩余回答能在一次请求内完成。

## Testing

agent-loop 回归测试覆盖 max-tokens、steer 续写、工具调用、后续请求携带已提交的工具结果、最终回答，以及粘滞的轮次结束原因。UI 测试覆盖本地化续写操作和思考内容自动展开。
