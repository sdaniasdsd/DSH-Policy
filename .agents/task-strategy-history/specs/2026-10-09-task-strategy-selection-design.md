# 上层策略选择与插件界面设计

日期：2026-10-09。设计阶段：供用户评审；尚未修改产品实现。

## 用户目标

在现有任务策略层之上，根据任务输入通过 LLM 选择合适策略。实现尽量简单，复用原版插件页面与可选问答体验。用户可以指定策略，也可以不回复，让任务按自动选择继续。原有同步作者决策、阶段替换与版本校验继续作为执行基础。

本次先接入显式策略入口，不接管所有普通聊天输入。插件配置页提供“自动选择 / 指定策略”，默认为自动；本次调用携带的明确策略优先于插件默认设置。不回复表示沿用已配置的自动流程，不构成权限审批。

## 方案选择

采用一个异步选择步骤，随后进入原有同步计划与执行链。直接修改同步作者接口会重新引入取消阻塞问题；重写根 Agent 输入循环会扩大消息归属与生命周期改动。此次保留现有执行循环，通过已存在的子任务能力实现选择。

## 模块与职责

| 模块 | 职责 | 依赖 |
|---|---|---|
| 上层选择入口 | 解析自动或指定模式；在异步工作之前按原始请求预留；返回一次接收回执 | 当前活跃所属 Agent、Jobs、策略注册表 |
| LLM 选择器 | 根据原始任务及策略描述，只返回一个已注册的策略 id | 原版无工具子 Agent、取消信号、有限输入输出与时间额度 |
| 原有策略模块 | 同步计算计划、检查执行能力、创建 Job、管理阶段与替换 | 既有 TaskRun / admission / executor |
| 插件配置前端 | 展示自动模式、指定策略、选择模型、等待设置及策略说明 | 原版插件 slots、共享 UI primitives、配置表单 |
| 可选用户征询 | 根 Agent 可以使用原版限时问答表达选择；超时后继续自动流程 | 原版 ask_user_question、userQuestions 投影与 UI |

作者策略函数继续保持有限同步计算。LLM 选择器不暴露文件、终端、派发、问答等业务工具；使用原版 `outputSchema` 时保留子 Agent 自有的 `structured_output` 结果提交机制。输出不包含执行计划、代码、工具名或权限配置。选择子 Agent 的提示与结果沿用原版 Session 记录，最终释放资源后才允许启动执行 Job。

## 入口与数据

新增上层接收操作，接收所属 Agent、原始请求和准入取消信号。原始请求包含 `requestId`、`task`、可选的选择模式及字符串偏好。选择模式使用带判别字段的自动 / 指定联合；先由拥有默认值的解析步骤生成明确模式，再开始执行。

自动模式调用选择器；指定模式验证策略存在后直接进入计划决策。原任务正文保留，不由选择模型重写。模型输出使用对象结构 `{ strategy: string }`，并在模型输出解析处检查它确实属于本次候选集。选择完成后再次查找当前注册策略；已注销的目标直接拒绝，不替换为其他策略。

回执包含原版 JobId、计划名称和实际选定策略，供调用方明确显示。原有 `submit`、显式计划 `start`、`inspect`、`requestSwitch` 与 `resume` 保持可独立调用。

请求编号的预留发生在选择模型启动之前。自动 / 指定模式及偏好参与请求内容指纹；相同所属 Agent 下，相同请求共享一次选择与一次执行，不同内容复用编号时拒绝。准入失败允许修正原因后重试。载体重新挂载不会让已经接收的任务重新选择。

## 用户选择与无回复行为

插件默认自动选择。用户可以在提交前指定策略，也可以主动要求先呈现选项。没有用户选择时，自动流程具备完整执行条件，不依赖一次问答结果才能启动。

需要选项征询时，复用根 Agent 的原版限时 `ask_user_question`，默认只短暂等待；不使用无限等待模式。超时是未收到答复，不伪造答复，不修改审批结果。根 Agent 沿用自动推荐，并使用同一个任务请求编号提交。明确指定的合法策略可以覆盖推荐。

不把问答调用藏在策略分发工具内部，不把原工具改名为策略工具：当前问答投影通过工具名称、已记录 schema 与结果识别可继续的问题，隐藏或改名会破坏恢复。迟到回复沿用原版新消息路径，不回填已结束的工具调用、不再次提交同一任务。若用户明确要求改变执行中的策略，调用方读取当前绑定版本并通过现有切换接口操作；终态任务不能被回复重新启动。

## 防呆与生命周期

- 空任务、空请求编号、无候选策略或不存在的指定策略，在模型选择或执行之前拒绝。
- 模型输出只接受本次候选策略 id；无效 JSON、未知 id、多选或额外执行内容不进入计划执行。
- 选择输入、输出和时间额度是有界配置。超时或取消传播给原版子任务，释放其资源后结算，不自动重试，不静默选其他策略。
- 选择器失败与用户未回复是两个不同结果：前者明确报错，后者使用既定自动模式。
- 所属 Agent 销毁、准入信号取消或载体卸载，取消尚未接收的选择过程；已被 Jobs 接收的执行保持现有所有权与取消规则。
- 所有提交路径统一使用服务侧去重；按钮禁用仅改善体验，不承担防重复执行的保证。
- UI 保存使用原版配置版本校验；模型、策略注销、断线与载体重载不造成前端展示虚假的保存或运行成功。

## 前端设计

名称：任务策略。说明：根据任务自动选择执行策略，也可手动指定。

复用原版插件页面的卡片、返回导航、表单、保存 / 放弃、状态和错误样式。独立的实验性前端贡献通过现有 slots 注册，运行时仅使用共享 primitives，不导入其他业务 UI 组件。页面随对应 Host 配置可用性挂载与卸载，保持实验性显式接入。

第一版页面只包含：默认选择方式、指定策略下拉框、选择模型、选择超时，以及只读策略说明。自动模式下隐藏指定策略输入；只有显式保存才改变默认配置。任务级选择优先，已接收任务不被配置保存重新选择。

另附静态界面设计稿，用于审阅布局和文案。其保存、提交与状态均为示意，不连接后端；实际实现需接入原版配置表单与服务结果。

## 验证与完成条件

源码行为测试覆盖：自动与指定分支、去重发生在模型调用之前、策略注销、模型无效输出、取消、超时、Owner 销毁、选择资源释放、准入失败重试和配置快照。

构建产物黑盒测试通过真实 Loader、Jobs 和子任务运行，断言相同请求只选择一次且只创建一个执行 Job。原版限时问答组合覆盖无回复后继续、及时明确选择、迟到回复不重复派发、取消与重载。

模型可见行为增加受支持 headless 入口的记录会话重放，验证选择输入输出、错误与后续成功可从 Session 还原。前端验证自动默认、指定选择、配置保存冲突、断线状态及插件卸载；真实页面组合检查中英文文案与原版样式。

本次不包含任意 DAG、任务持久化、进程重启恢复或默认聊天入口接管。
