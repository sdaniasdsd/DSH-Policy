# 策略版默认任务入口设计

日期：2026-10-10。本文为待审阅设计，不表示本机应用已经具备这些行为。

## 目标与验收

策略版中的普通用户任务默认经过顶层策略入口。用户可以指定策略，也可以不回复，由入口自动选择。聊天应显示所选策略、可解释 Token 估算、阶段进度和终态。执行沿用现有 TaskRun、Jobs、子任务与官方插件；子任务保留执行能力，不再次进入顶层策略选择。

验收必须通过本机安装产物中的真实普通聊天入口，不能只证明目录中有 12 条策略，或者手工调用 task_strategy_submit 成功。

## 已核对的源码基础

- [策略载体](../../../packages/experimental/task-strategy/src/cordis.ts) 已提供 submitTask、阶段执行和所属 Agent 校验，目前只向根 Agent 注册四个工具。
- [策略选择器](../../../packages/experimental/task-strategy/src/selector.ts) 已提供有截止时间、输出限制和取消传播的结构化选择。
- [Agent 扩展点](../../../packages/core/agent/src/runtime-types.ts) 提供 agent/pre-step；监听器须保留 next() 的消息处理结果和原版消息归属。
- [工具服务](../../../packages/core/tools/src/index.ts) 提供按 Agent 注册的 restrict 与 guard；执行检查覆盖通过原版工具服务派发的嵌套调用。
- [策略界面挂载](../../../packages/experimental/task-strategy/src/client/mount.ts) 目前提供插件配置卡片，尚未提供聊天运行卡片。

## 接入方式

新增入口协调能力，由策略版 bundle 默认启用，通过原版 Agent、工具、Session 和 Jobs 扩展点接入，不重写 AgentLoop。官方组合默认行为保持现有配置。设置页提供策略入口开关，保存影响未来输入；已接收任务保留原有绑定。

普通消息首先进入协调器。协调器根据当前任务状态和原始输入，将其归为普通对话、新任务、当前任务补充、进度查询、取消或切换请求。需要模型判断时，使用有界结构化模型调用，只允许返回路由结果，不开放执行工具。明确的界面操作使用类型化命令，避免再让模型猜测。

普通对话由根 Agent 回答；新任务由协调器自动调用 submitTask。根 Agent 负责沟通、读取任务状态和汇总结果，业务执行交给策略创建的子任务。顶层不依赖根模型主动记住调用派发工具。

## 模块与接口职责

| 模块 | 输入与输出 | 所属职责 |
|---|---|---|
| 输入协调器 | 原始 UserMessage、当前任务状态、取消信号 → 路由结果或接收回执 | 原始消息归属、稳定请求编号、一次派发、后续消息关联 |
| 路由判断 | 原始输入与任务摘要 → 对话 / 新任务 / 补充 / 查询 / 控制意图 | 有界模型判断；不修改任务正文，不执行工作 |
| 现有策略服务 | TaskIntakeRequest → TaskReceipt | 自动或指定选择、成本目录、准入和任务执行 |
| 根 Agent 工具限制 | 当前 Agent 与调用 → 可见工具集合、执行拒绝原因 | 防止通过文件、Shell、任意子任务或 PTC 绕过策略执行 |
| 聊天状态投影 | 已记录入口事实、现有 Jobs 状态和 TaskRun 视图 → 运行卡片 | 展示状态、重连刷新、错误和用户控制 |

实现时将入口协调、路由判断与工具限制放在独立模块，载体仅负责装配与生命周期。扩展现有服务接口时更新全部调用方和生成类型；不另建第二套 Job 或执行器。

## 工具与消息边界

1. 根 Agent 默认只获得策略目录与预览、受控任务操作、Jobs 查询与取消，以及用户交互能力。业务执行工具从模型展示中移除，并在工具服务执行处检查；仅隐藏 schema 不算完成。
2. 控制操作按任务所有权校验。顶层策略模式下，显式执行计划和任意子任务派发不作为绕过自动入口的路径。
3. 执行和选择子 Agent 不安装入口协调器；依据原版子任务来源与所有权识别，不能靠任务文本中的标记识别。
4. 原始任务正文保留。附件、工作目录、模型路由和必要的会话上下文须显式传递；当前文字任务接口无法表达的附件不得被静默丢弃。无法准入时明确报告限制。
5. 普通追问、补充、审批回复、Jobs 通知和运行反馈不自动成为新任务。输入含歧义时先展示理解并征询用户，不默认重复执行。
6. 新任务请求编号由宿主根据原始消息身份生成，不能让模型每次随机生成。重复消息或重试在选择模型运行前去重；同一编号与不同内容冲突时拒绝。

## 生命周期与失败处理

选择中的取消沿用现有 intake 信号；接收后的取消沿用 Jobs。关闭、卸载和所属 Agent 销毁仍遵守现有生命周期规则。入口判断有独立配置的截止时间、输入字节和输出 Token 上限；失败不得转为根 Agent 直接执行。

已有活跃任务默认关联补充或控制意图。新增独立任务必须明确识别并形成独立请求。策略切换使用现有 expectedBindingEpoch，在阶段屏障提交；迟到回复不会产生第二次派发。

模型可见的路由结论、策略回执和输入上下文必须通过可记录渠道进入会话。聊天卡片以 Host 事实为准，不以按钮点击或模型宣称作为已执行依据。断线不触发重新派发；重连读取既有状态。进程重启沿用当前不支持自动恢复执行的限制，显示已中断状态，不能自动重跑旧任务。

## 前端与成本

聊天运行卡片显示：理解请求、选择策略、已选策略及估算、执行阶段、完成 / 失败 / 取消。接受前尚无 JobId，以原始请求身份展示；接受后关联原版 JobId。选择失败与执行失败分开显示。

复用原版聊天插槽、共享 primitives、Jobs 输出和配置表单。策略页面增加入口设置；聊天卡片提供当前任务的取消和阶段结束切换操作，所有命令由 Host 再次检查权限、绑定版本和状态。

沿用现有子任务成本估算，明确显示已知输入、阶段和任务数、场景假设及未知项。入口判断、策略选择和根 Agent 汇总属于额外用量，不能被现有子任务估算冒充为已经计入。高档策略不因有更多阶段而成为默认首选；满足任务要求后比较成本。

## 验证与本机交付

- 白盒：消息分类边界、原始正文与附件保留、去重、非法路由、无候选、超时、取消、子任务不递归、Owner 销毁和卸载。
- 真实组合：通过普通用户输入自动创建一次策略任务；根 Agent 直接执行和 PTC 嵌套绕过被拒绝；执行子任务能够使用官方插件完成工作。
- 黑盒：使用现有 API 和模型，从桌面聊天执行一个有明确可观察结果的低档任务；核对策略选择、阶段、结果、Token 估算和会话记录。
- 前端：选择前状态、运行状态、切换版本冲突、失败、取消、断线重连、无回复继续，以及插件设置保存。
- 打包：执行规范 Windows 构建和安装产物检查，确认 bundle 默认启用入口，不能只检查源码构建成功。
- 更新：先备份安装目录和相关配置；检测活跃任务，待结算后替换完整程序目录；保留现有凭据、模型、会话和用户插件，启动后重新核对普通聊天入口。

## 范围

此次交付包括默认入口、根 Agent 工具限制、聊天运行卡片及本机更新。保持现有静态阶段计划与替换机制，不新增任意 DAG、跨进程任务恢复、自动执行重试或独立的权限系统。
