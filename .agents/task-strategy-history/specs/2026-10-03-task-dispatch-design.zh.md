# 任务分发层——设计提案

[English](2026-10-03-task-dispatch-design.md) | 中文

## 概述

本文是待评审草案，不是已实现行为的说明。上层决定分发哪些任务以及何时分发；原版 DSH 运行时执行各项任务。新增部分展示任务活动和结果，不修改 agent loop（智能体循环），不引入外部工作流框架。

## 范围与假设

第一版作为显式启用的 Cordis 插件运行在单个 DSH 进程内。父 agent 提交独立任务，立即获得任务 ID。提交工具返回后，分发器继续持有已接受任务；父 agent 释放或分发器卸载会取消任务并等待其完全停稳。父 agent 的普通轮次结束不会取消任务。

拟定的首版通过模型工具和类型化服务提供提交、并发限制、列表、查看和取消功能。不包含新图形看板、自动拆解任务、依赖图、自动重试、分布式执行器或崩溃恢复。这些是需要评审的首版假设，并非此前已经约定的需求。

任务记录和有上限的活动摘要首版保存在进程内存中。原版 DSH 的会话持久化保持不变。重启会丢失分发队列；插件不会自动重发执行结果不明确的任务。即使子会话已经持久化，也不代表分发队列能够恢复。

## 接入方式

在现有 subagent 服务之上增加插件。改造工作流引擎会使分发依赖脚本执行和前台结果收集；外部 SDK 服务则增加进程协议与部署。插件方式保留本地自定义分发策略，并保持 DSH 执行逻辑不变。

已核实的入口是 [subagent 服务](../../../packages/subagent/subagent/src/index.ts)中的 `ctx.subagents.start(name, request)`。[运行句柄和结果类型](../../../packages/subagent/subagent/src/types.ts)提供子任务身份、可选的本地 agent、最终结果和异步资源释放。首个适配器使用原版进程内 spawn 提供方。独立会话隔离的是对话状态，不是共享文件或外部副作用。

## 分发与观察

拟新增服务 `ctx.taskDispatcher`，提供 `submit`、`list`、`get`、`cancel` 和观察者注册。拟新增消费工具为 `task_dispatch`、`task_status` 和 `task_cancel`。这些名称是提案，不是 DSH 现有 API。所有操作限定在所属父 agent 范围内；其他父 agent 无法通过猜测 ID 查看或取消任务。

提交参数包含任务种类、标签和明确的提示词。配置中的任务种类选择允许的执行预设；未知种类在接受前报错。上层调用方选择任务内容和顺序。分发器按先入先出顺序准入，并使用经过验证的正整数并发上限。它不规划任务、不改写提示词、不评判结果，也不自动注入后续消息。

任务进入队列前获得带品牌类型的任务 ID；子任务发布后补充子会话 ID。同一父 agent、同一进程中的重复调用方请求 ID 返回原任务；请求内容冲突则报错。启动中的任务占用并发名额，只有子任务清理结束才释放名额。

任务生命周期为 `queued`、`starting`、`running`、`cancelling`，最终进入 `completed`、`failed` 或 `cancelled`。独立的活动字段描述最近观察到的步骤或工具操作。只有明确的 DSH 交互事件才能表明正在等待输入；没有输出不意味着等待或失败。

观察者收到独立快照，其中包含任务内序号、时间戳、任务 ID，以及已知时的子会话 ID。启动前注册监听器，避免丢失早期事件；通过现有 subagent 生命周期及父级归属关联发布前的子事件。保留事件数量和预览大小由配置限制。历史被截断时明确标注。观察者抛错不影响执行或其他观察者。

以运行句柄的最终结果映射任务终态，并保留原始结束原因。`completed` 仅表示子任务正常结束，不代表已经独立验证用户目标。拒绝、token 上限、错误或未知的非正常结束原因都标记为执行失败并保留原始原因。基础设施异常与助手输出分开展示。绝不把 agent 空闲作为任务成功的证据。

## 取消与资源归属

每个已接受任务有独立取消控制器。取消排队任务会阻止创建子任务。启动期间取消会中止启动并等待清理。取消已发布的子任务会传递取消请求，并等待结果及资源释放。取消请求在执行停止前显示为 `cancelling`；已确定的任务终态不再改变。

分发器持有每个返回的运行句柄，并在所有结束路径中释放它。关闭时拒绝新提交、关闭观察通知、取消待执行及运行中的任务，并等待完全停稳。一个任务失败或取消不影响无关任务。清理失败必须可见；如果执行可能仍然存在，不得静默释放并发名额。

并发任务可能共享文件和外部系统。首版调用方必须提交互不冲突的工作；插件不提供文件系统隔离、自动合并或外部副作用恰好执行一次的保证。可能冲突的写操作必须串行分发。DSH 原有权限及审批策略继续生效。

## 验收证据

实现验收需要针对队列顺序与容量、任务身份隔离、早期事件、任务种类校验、重复提交、观察者异常、子任务失败以及启动前后各阶段取消编写定向测试。还需要覆盖卸载与停稳、父级权限检查以及事件保留上限。

无密钥录制会话场景必须通过实际工具消费方提交任务，使用原版 DSH 驱动和测试模型提供方，覆盖并发子任务活动、状态查询及最终结果。模型可见输出需要快照覆盖。实现同时运行类型检查和相关文档检查；证明调度行为不需要付费模型调用。
