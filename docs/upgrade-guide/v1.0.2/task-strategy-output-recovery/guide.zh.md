# 任务策略输出恢复

[English](guide.md) | 中文

## 变更

本地预设任务过去在输出截断后持续续跑，直到其他执行限制使其停止。现在默认允许四次续跑，并在连续两次没有新增拼合文字或成功工具结果时停止恢复。中断结果保留子会话和部分输出。路由和选择在截断后重试一次，再报错或使用配置的兜底；模型未声明 off/none 时使用其声明的最低思考力度。

风格插件为每次续跑提供 300,000 毫秒的新时间窗口，极端高档为 600,000 毫秒。用户取消始终有效。自定义计划在未明确配置续跑时限时，仍使用原总截止时间。

## 迁移

1. 自定义本地预设计划可将 `TaskStep.continuation.maxAttempts` 设为 0–16 的整数；零关闭自动续跑。只有需要每次续跑获得新的有限时间窗口时，才设置 `continuation.timeoutMs`。外部执行器任务不接受这些控制。
2. 在风格插件配置中修改 `continuation` 或 `extremeHigh.continuation`，限制额外次数与时间。最长激活时间为首轮时限加上 `maxAttempts` 乘续跑时限，不含清理时间；无进展检查可以提前停止恢复。
3. 确认中断任务保留会话和诊断，且当前阶段完成前不会启动依赖阶段。手动重试前检查部分文件。这些控制不提供进程重启恢复，也不会为独立 Policy Bundle 补上官方尚未开放的续跑 API。
