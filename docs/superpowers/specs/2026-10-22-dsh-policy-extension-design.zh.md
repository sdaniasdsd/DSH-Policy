# DSH Policy 独立扩展框架设计

[English](2026-10-22-dsh-policy-extension-design.md) | 中文

## 目标

将 DSH Policy 从当前的完整源码版 Policy Edition 中拆出，成为可独立安装到官方 DSH 的扩展。在此过程中保留现有任务反馈和策略切换行为，并让每个扩展发行版对应一个确定的官方 DSH 版本及源码提交。

## 职责边界

| 官方 DSH 负责 | Policy 扩展负责 |
|---|---|
| 应用启动、profile、插件安装与启用 | 策略目录、选择规则和预检校验 |
| 模型、工具、Agent、Subagent、Session 和 Jobs | 任务级策略绑定、阶段编排和反馈路由 |
| Workflow 脚本执行和 Web 插件扩展点 | 策略配置、进度和策略控制 |
| 运行时兼容检查和 profile 包管理 | 针对锁定 DSH 版本测试的兼容适配层 |

扩展不再携带替代 DSH 应用、模型网关、Agent loop、Session 存储、Jobs 系统或插件管理器。它由一个 profile Bundle 和其拥有的插件组成，通过官方 profile 插件入口安装。

## 执行与反馈模型

Policy 控制器继续拥有一个已接收任务的策略绑定、已完成结果、阶段游标、限制和控制命令。它可以调用官方 Workflow 脚本作为执行适配器，但一次脚本运行既不是持久任务身份，也不取代策略控制器。

拆分后保留以下运行中任务行为：查看进度并取消；为下一个未开始阶段追加有界的人类输入；预留策略替换，并仅在当前阶段排空后提交；拒绝过期的绑定 epoch；替换失败后恢复原策略；以及在使用 DSH 原生成员执行器时向活跃成员发送消息并访问任务范围内的版本化记录。正在执行的阶段继续使用启动时捕获的指令和执行器。反馈在明确的阶段边界改变后续工作，不会改写正在执行的脚本。

Workflow 脚本可以在单次运行中根据结果分支。扩展会在完成本次运行后，再决定是否启动后续阶段或脚本。如果官方 Workflow 契约没有暴露现有反馈能力所需的子任务归属和控制句柄，该策略就继续使用 DSH 原生成员执行器。不能在执行器无法投递消息时，仍宣称支持成员实时消息。除非现有运行时本来就支持，否则本次不增加进程重启后的任务恢复能力。

## 扩展版本与运行时的对应关系

每个已发布的 Policy 扩展版本只对应一个精确的官方 DSH 运行时版本和一个上游源码提交。扩展包的发行元数据记录这两个值，并为其使用的 DSH 服务声明精确版本的 peer 依赖。已发布的包清单不得包含 `workspace:*` peer 依赖。

发行检查会核对元数据、包 peer 版本、锁文件和被测试的 DSH 源码是否指向同一版本组合。DSH 版本不匹配时，插件兼容性检查必须拒绝安装；常规安装路径不提供自动回退、宽泛兼容范围或版本豁免。支持另一个 DSH 版本时，必须发布一个针对该版本单独测试、拥有独立映射和兼容结果的扩展版本。

DSH 版本标识运行时契约；当版本标签或包仓库不足以重现该契约时，上游提交用于固定具体源码。Policy 自身仍独立递增版本，因此多个 Policy 修复版本可以对应同一个 DSH 发行版，但一个 Policy 版本不能同时宣称兼容多个官方 DSH 版本。

## 已考虑的方案

**继续维护完整 Policy Edition 分支。** 这种方式保留了对运行时实现的直接控制，但每次上游变更和安装包更新都继续成为我们的维护负担，也不符合独立扩展目标。

**只发布静态工作流脚本和配置。** 这种方式易于安装，但无法持有当前任务身份，也无法实现现有的阶段边界策略替换、恢复和反馈路由，因此会丢失用户要求保留的行为。

**让官方 Workflow 完全承担任务运行时。** 这种方式会简化执行器，但公开 Workflow 契约是前台脚本运行，不能独立提供现有策略控制器的所有任务级反馈和切换语义。Workflow 应作为执行适配器，而不是策略状态的所有者。

## 验证目标

- 干净的官方 DSH profile 可以安装并启用扩展 Bundle，不依赖 Policy Edition 桌面应用或源码工作区。
- 扩展的运行中任务反馈测试保留当前语义，包括阶段边界切换、过期 epoch 拒绝、恢复，以及已支持的成员消息与任务记录。
- 使用 Workflow 脚本的策略可以读取此前阶段结果并选择后续阶段，同时保留整个任务的身份和限制。
- DSH 运行时版本不符合扩展精确声明时，安装和启动均会拒绝。
- 每个扩展发行版的元数据、精确 peer 依赖和被测试的上游提交相互一致。
- 扩展包可以在干净的消费者安装环境中构建和测试，不依赖 workspace 别名或未声明的 DSH 源码导入。

## 范围

第一阶段将策略控制器、策略定义、反馈接口和必需的 Web UI 迁移到 DSH 外置包；用官方 profile 安装与插件管理替换桌面端的自动 profile 修改。在改变当前支持的运行时组合前，先增加精确的 DSH 与 Policy 发行映射及兼容性验证。

本设计不承诺一个 Policy 版本兼容多个 DSH 版本、不增加超出现有行为的重启恢复、不控制没有暴露相应接口的原生外部 CLI 会话，也不提供替代桌面外壳。首个目标是一个锁定的官方 DSH 发行版及其支持的 Web profile。
