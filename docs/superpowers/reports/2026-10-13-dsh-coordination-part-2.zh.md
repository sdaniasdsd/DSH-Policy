## 已交付行为

执行器可使用可选的第五个 `TaskExecutorContext` 参数，启动、查询并显式继续属于自己的本地成员。继续执行保留会话及历史，以原任务的确切所有者作为输入发送方，并返回已接收消息身份及该确切 activation 的结果和清理句柄。旧清理句柄不能关闭后续 activation。

结果保留原始终止原因，包括失败、token 上限终止和中止。`settled` 表示已捕获结果，不表示成功。捕获失败返回带有已接收身份的 `unobserved`，不会自动重放。不支持的继续操作保留实际能力错误，不创建替代会话或后端。

继续成员会话保留已捕获的 token 上限和结构化提交 schema。普通子级及执行器成员共用任务的同步并发预留，清理完成后释放。控制器步骤和成员接收尝试计入原任务累计额度。完整请求及结果受大小限制。执行器结束或任务取消时关闭成员接收，并等待所属工作清理，包括尚未发布的启动过程。

已有四参数适配器继续运行。只有作者显式使用可选上下文时，适配器才创建本地成员。Host 继续接口可通过 `resume` 恢复未持久化的 token 和 schema 控制；在线目标拒绝重建覆盖参数。

## 验证与审查

最终专项测试通过 **9 个文件、363 项测试**。Loader 测试验证原始 Job 和会话身份、两次已接收消息、JSONL 发送方、保留的模型历史、显式恢复、取消及清理、能力缺失和结果捕获不确定性。另有四个回归测试先复现审查问题，再验证修复：继续执行的 token 上限、结构化提交、并行执行器预留和普通子级与成员混合并发。

Host TypeScript 编译、定向 lint、三个暂存文档配对及 **479 个源类型和 479 个配对衍生类型** 等价检查通过。暂存源码的 API 生成及持久化历史检查通过，本份未扩展持久化 schema。最终保留核对确认 21 个原文件逐字节一致，五个共同编辑文件保留此前内容，已有翻译元数据的不相关章节保持不变。

一次独立最终审查发现两个 Important 问题，没有 Critical 或 Minor 问题。两个 Important 问题已在一轮修复中完成回归验证。没有延后的 Minor 项；未再次发起审查。

审查者未判断后续黑板、会议及采纳协议、原生后端继续能力、此前未提交改动，以及另行修正的依赖位置。运行时测试通过真实 Loader 服务使用确定性的模型流，不证明外部模型表现或完整原生策略链路。

## 执行裁决

以下为执行记录中的全部裁决，按记录顺序列出：

1. 保留用户明确选定的源码目录，仅暂存本份改动。**代价：** 混合待提交改动需要独立保留核对。
2. 第 2 项任务的 hook 检查通过后，格式化与未暂存内容恢复发生冲突。用本份起始副本恢复全部原文件，用限定暂存区恢复本份文件；检查已通过后仅跳过一次 hook 执行。**代价：** 恢复风险要求最终保留核对，核对已通过。第 1、3 项任务的正常 hook 均通过。
3. 断言真实 Loader 的 `aborted` 终止原因，不将其归一化为 `cancelled`。**代价：** 适配器需解释原始终止值。
4. 从暂存源码生成 API 文档，排除此前本地功能改动。**代价：** 在此前改动提交前，整个工作副本的新鲜度检查可能不同。
5. 通过显式冷恢复参数保留 `maxTokens` 和 `outputSchema`，不扩展持久描述。**代价：** 直接调用 Host 接口时需提供未持久化的控制参数；在线目标拒绝重建覆盖参数。
6. 跨执行器成员和普通子级同步预留并发额度。**代价：** 超额嵌套启动明确失败，不进入隐式等待队列。

7. 让已有取消测试按接收会话区分挂起的工作成员，不依赖全局请求先后。追踪证明，若取消发生在子级启动前，主 agent 会错误消耗挂起响应。**代价：** 测试响应路由依赖其明确的主会话身份；原取消断言保留。
