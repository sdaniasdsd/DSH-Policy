## 已交付行为

成员在 activation 发布时登记，在清理时移除。任务原始、仍存活的所有者可以查询成员并发送非空、有大小限制的消息。仅活跃接收模式拒绝空闲、不存在或正在关闭的目标，不恢复这些目标。普通 Subagents 消息保留默认行为。

模型获得查询及发送工具，并支持自定义前缀。查询在必要时省略详细结果，以在输出限制内保留完整成员身份。回执标识消息已接收，不表示成员已处理或采纳。原生执行器成员不登记为 DSH 成员，不支持的投递不会切换后端。

| 提交 | 改动 |
| --- | --- |
| `active inbox API` | 核心仅活跃消息接收模式 |
| `owner-scoped member registry` | 任务所有者范围内的活跃成员登记 |
| `owner-scoped message service` | 精确所有者消息服务与任务生命周期取消 |
| `LLM tools and documentation` | 模型工具、文档及 API/持久化投影 |
| `Part 1 delivery` | 历史结果超过工具输出限制时仍可查询成员 |

可选活跃成员展示字段扩展了实验性持久化 entry 视图。双语持久化确认记录说明了 schema 改动；该字段不授予恢复会话的权限。

## 验证与审查

最终针对性测试通过 331 项，覆盖六个文件：task-strategy 的 adapter、成员、消息和查询测试，以及 Subagents 的 continuation 和 control 测试。测试使用真实 Loader、AgentLoop、Jobs 与 Subagents。消息投递通过 JSONL 记录及后续模型请求验证。模型流采用确定性测试输入，不连接外部模型服务。

Host TypeScript 编译通过。类型等价检查覆盖 479 个主块及 479 个配对派生块，全部通过。暂存文件的双语、lint 和空白检查通过；已提交源码的持久化检查覆盖 64 个根与 15 条历史记录。未运行整个仓库测试。此前未提交改动仍在，因此整个工作副本的生成器新鲜度检查可能产生差异。

独立的已提交范围审查发现一个重要问题：前序结果较大时，查询可能失败并隐藏后续正在执行的成员。真实 Loader 回归测试复现了失败，保留协作字段的有限输出修复了问题。修复后最终测试通过。没有严重发现或延期的小问题。

保留检查确认 21 个此前修改文件与开工副本逐字节一致。5 个共同编辑的源码/Markdown 文件排除本份新增内容后与开工副本一致。提交钩子曾无法恢复它隐藏的未暂存改动；已用开工副本恢复，再作限定范围提交。最终修复正常通过钩子。本报告提交后清理该计划的临时工作目录；源码和此前工作保留。

## 执行裁决

以下按执行顺序记录裁决及其实际代价。

1. 按用户选择在当前 main 源码工作，不另建工作目录、不提交无关工作。代价：工作树继续包含多份待提交改动，必须限定暂存范围。
2. 仅格式整理后复用已观察到的最终测试证据登记步骤完成。代价：不为登记重复运行同一测试；最终行为修复另有新一轮测试。
3. 从暂存源码生成 API 与持久化产物，排除此前本地改动。代价：此前工作提交前，整个工作副本的生成器新鲜度可能不同。
4. 钩子恢复失败后使用开工副本恢复，并在必要检查通过后单次绕过该钩子运行。代价：恢复可能丢失此前工作；保留审计核对原稿，最终修复正常通过钩子。
5. 会话继续/重启、成员互发、共享记录、恢复流程及会议留到后续交付。代价：第 1 份只支持所有者向执行中成员投递。
6. 原生后端协调能力在适配器验证支持后再交付，本份只显式拒绝不支持的请求。代价：本份不提供原生协调，也不替换后端。
7. 消息接收与处理、采纳分别对待。代价：调用方需等待后续成员证据，才能认定补充指令已落实。
8. 已提交范围审查不包含此前未提交工作，另行审计其保留情况。代价：此次审查不能验证此前功能；保留检查及限定暂存保证它们留在源码中。
